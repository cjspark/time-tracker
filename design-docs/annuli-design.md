# 第一部分：设计基础（Why）

## 一、这个 app 是什么

Annuli 是一个**温柔的自我目击者**。

用户打开它的时刻，往往带着一点隐隐的焦虑：我这段时间过得好吗？我有没有在往正确的方向走？我有没有善待自己？

Annuli 的任务是诚实地回答这些问题——但用一种让人放松、而不是更焦虑的方式。

它不是 KPI 仪表盘，不是打卡机，不是效率优化工具。它更像一个很懂你的朋友，坐在咖啡馆的对面，陪你翻翻最近的日子，温柔地说：你做得比你想象的要好，这里有一点可以调整，别着急。

---

## 二、核心使用场景

在为任何界面做决策之前，先问：**用户在这个场景下是什么状态？**

| 场景 | 时刻 | 用户状态 | app 应该给予 |
|---|---|---|---|
| 睡前复盘 | 晚上 10–12 点 | 有点疲惫，轻度焦虑，想知道今天值不值 | 温柔的肯定 + 清晰的总结 |
| 周末整理 | 周六/日上午 | 较放松，有心情回顾，想看看这周的自己 | 宏观视角 + 激励感 |
| 突然想看 | 任意时刻 | 随性，走在路上或等人时 | 最重要的信息一眼可见，不需要思考 |
| 记录当下 | 活动进行中/刚结束 | 在流动中，不想被打断太久 | 快速完成，零负担 |

**核心原则：app 服务用户的心理状态，而不是强行改变它。**

---

## 三、五条设计原则

### 1. 鼓励优先 Encouragement First

数据永远以"你做了什么"为主视角，而不是"你没做什么"。

- ✅ 显示完成的时间、达成的目标
- ❌ 不显示"还差多少"、"本周低于均值"等负向框架
- 进度条展示已填满的部分，空白部分静默存在
- 情绪分布图里，正向情绪排列靠前、颜色更饱和

**视觉对应**：完成状态用暖色系标注，完成感 > 数字精确度。

---

### 2. 无压记录 Zero Guilt

忘记记录不是失败，是正常的人类行为。app 永远不惩罚空白。

- ❌ 不显示连续打卡计数（streak）
- ❌ 不显示"已断签"、"本周记录率 60%"等提示
- ❌ 不发送"你今天还没记录！"的推送
- ✅ 空白日期在日历上静默，不标红，不特别强调
- ✅ 如有推送，语气为邀请性（"想翻翻这周？"而非"快来记录！"）

**交互对应**：记录入口随时可达，但不突出地"呼唤"用户。

---

### 3. 随意浏览 Casual Browsing

信息密度低，主要内容一眼可见，深挖是可选项而非必须项。像翻杂志，不像看报表。

- 每个卡片只传达一个核心信息
- 次要信息默认折叠或降低视觉权重
- 页面不超过 3 层信息层级

**布局对应**：留白是设计的一部分，不是浪费。一屏内容宁少勿多，接受用户滚动。

---

### 4. 正反馈驱动 Positive Loop

用户因为"看到自己"而想回来，不是因为"怕断掉"而回来。

- 每次打开，用户感受到"被接住"——有内容呈现自己的状态
- 产出目标完成后，有值得期待的视觉反馈（不是一个简单的 ✓）
- 奖励机制设计为惊喜和仪式感，而非压力
- 复盘页让用户感受到"哇，我做了这些"，不是"我只做了这些"

**交互对应**：产出目标勾选有满足感的动画；奖励兑换有仪式感。

---

### 5. 安全容纳 Safe Holding

负面情绪的记录不会被系统惩罚或忽略。低落是数据，不是失败。

- 情绪标签里没有"坏"选项，只有五种真实状态（😊愉悦 / 😌平静 / 😐还行 / 😔低落 / 😤压力）
- 低落情绪的记录在视图里被温柔地呈现，不用警告色
- 复盘里展示情绪分布时，低落时段旁边是"这段时间发生了什么"的空间，而不是评判

---

## 四、内容语气（Voice & Tone）

Annuli 说话的方式：像一个有洞察力的朋友，不是一个系统通知。

| 场景 | ❌ 不用 | ✅ 用 |
|---|---|---|
| 空状态 | "暂无数据" | "这周还很安静，先从今天开始" |
| 记录成功 | "保存成功" | "记好了" |
| 目标完成 | "任务已完成" | "做到了 🎯" |
| 奖励兑换 | "兑换成功" | "好好犒劳自己" |
| 引导创建 | "请添加领域" | "想先追踪哪块生活？" |
| 错误提示 | "网络错误，请重试" | "有点问题，稍后再试试" |

**原则**：第二人称"你"；句子短，动词优先；不说教，不催促；最多一个 emoji。

**emoji 使用边界**：emoji 只在**记录打情绪标签**时出现（愉悦/平静/还行/低落/压力）；**复盘报告里全程不出现 emoji**——图例用色点 + 名字，建议语纯文字。原因：报告是回看自己的严肃时刻，emoji 会显得轻佻、画蛇添足。

## 五、明确的反模式

| 反模式 | 违反的原则 |
|---|---|
| Streak 连续计数 | 无压记录 |

# 第二部分：视觉系统（What）

> 所有视觉规格均由"第一部分"的五条原则推导而来。

## 六、色彩哲学

整套 app 采用**莫兰迪低饱和大地色系**。莫兰迪色系之所以契合 Annuli 的五条原则：

- 低饱和 → 不刺激，不制造压力感（安全容纳）
- 暖色基底 → 接纳、温柔、有人情味（鼓励优先）
- 均匀明度 → 没有视觉"警报"，不突出负面信息（无压记录）

所有颜色遵守三条统一规则：

1. **饱和度统一**：所有主体色饱和度控制在 **25%–42%** 之间
2. **明度分层**：背景/卡片在高明度区（88%–97%），主体色在中明度区（55%–70%），文字在低明度区（25%–45%）
3. **色相均匀分布**：功能色沿色相环均匀铺开，避免相邻色相打架

> 关键：不用纯色、不用高饱和。每个色都像"蒙了一层灰"，这是莫兰迪协调感的来源。

## 情绪水色引擎 MoodBlend（UI 库第一个色彩引擎）

复盘页水晶球每块水的颜色，由该类活动内的情绪时间分布实时混合而成。这是 UI 库第一个可复用色彩引擎：`MoodBlend(情绪分布) → Color`，日历时间块的情绪叠加、生命树果实成熟色等将来都可调用它。一处定义，处处一致。

**为什么不能在 RGB/HSL 里直接平均**：对冲色相（绿 × 赭红）直接平均会得到浑浊的棕（"泥色"），且明度过渡不符合人眼感知。

**算法（在 OKLab 感知色彩空间混合）**：
1. 每种情绪基色 → OKLab (L, a, b)
2. 权重 = 各情绪时间占比，取 `权重 ^ 主导偏向` 后归一化（主导偏向 > 1 让占比最大的情绪主导水色，而非平均成灰）
3. L、a、b 按归一化权重加权平均（在 a/b 笛卡尔平面混合，天然正确处理色相环，不绕错方向）
4. a、b 乘「情绪浓度」系数放大彩度
5. OKLab → sRGB 上屏

**确认参数（2026-09-30 定稿）**：
- **情绪浓度（chroma）= 3.2** —— 莫兰迪低饱和是给背景/卡片的，水本身要够浓才能分辨情绪
- **主导偏向（dominance）= 3.5** —— 水色基本呈现"主导情绪色"，混合情绪也以最强者为主

> 权衡：主导偏向拉满时，混合情绪基本只显示最强的那个，牺牲细微层次换取辨识度。日后若要更多混合层次，把 dominance 调低即可。

**参考实现**：见 [liquid-lab.html](./liquid-lab.html) 的 `blend()` 与 OKLab 转换函数。

## 液体渲染配方（水晶球质感）

平的色块没有液体感。真实液体质感来自四层叠加：

1. **深度饱和渐变**（体积感核心）：水面浅而淡、水底深而浓（模拟 Beer-Lambert 光衰减）。实现：对基色在 OKLab 里，顶部 L+ / C−，底部 L− / C+，做 180° 垂直渐变
2. **波动水面**：两层 SVG 波形以不同速度、透明度横向漂移，形成会晃的曲面（meniscus）
3. **高光 specular**：玻璃曲面左上一处柔和白色反光点
4. **气泡**：少量缓慢上升、淡出的小气泡，增添生命感

**玻璃外壳 vs 情绪液体**：外壳走苹果 Liquid Glass 玻璃材质（透明 + 折射 + 高光），内容是上述情绪液体——玻璃是壳、情绪是魂，两者叠加，不做成缝合怪。iOS 26+ 可用原生 `.glassEffect()`；更老系统需自行用渐变 + 模糊手搓。

**参考实现**：见 [liquid-lab.html](./liquid-lab.html)。

## 九、动效规则

动效服务内容，不表演。**完成感 > 炫技感**。

| 类型 | 时长 | 缓动 |
|---|---|---|
| 标准操作（按钮/切换）| 0.3s | spring，damping 0.75 |

# 第三部分：页面规格

## 十、生命树页面（核心视觉）

整体气质：自然生长 / 治愈系 · 仅浅色模式 · 写实森林场景（Forest 风）
签名元素：**多主树冠共生、单叶程序化排布的年度生命树** —— boldness 全花在这里，其余页面克制。

### 子页面 1：今年的生命树

**整体构图（从下到上）**
```
        ·· 飘落的树叶 ··
     ╭──────────────────╮
     │   次冠  次冠       │  ← 小项投入（黄绿→深绿）
     │  ╲  主树冠  ╱ 次冠 │  ← 大类（橄榄绿）
     │ 背景冠 ╲│╱ 背景冠   │  ← 装饰（低透明绿）
     │      ╲ │ ╱         │
     │       侧枝（有弧度）  │
     │        │           │
     │      主树干（崎岖）   │
     │       ╱│╲          │
     ═══════土壤═══════════   ← 底部扎实，比顶部粗
              2026            ← 年份大数字
```

**树冠三层（z-index 由低到高）**
1. **背景树冠**：纯装饰，`leaf-bg` 透明度 0.4，密集填充
2. **主树冠**：每个领域一个冠团，`leaf-main` #7A9B6E
3. **次树冠**：围绕主冠，颜色随时间 `leaf-sub-young` → `leaf-sub-mature`，时间越长越深绿+树叶越多

**树叶排布算法**
- 单片树叶 PNG（3–4 种），每冠团用固定随机种子（domain id）在圆/椭圆区密集散布
- 树叶数量 = f(投入时间) 连续增长，每片随机轻微旋转
- `filter: hue-rotate / saturate / opacity` 实现三层色差

**花与果实（产出目标）**
- 完成：陶土红果 `fruit-done` #BC6A5A
- 进行中（低进度）：花（雾粉/芥末黄）
- 进行中（中高进度）：青绿果 `fruit-progress` #8FA878

**树干**
- `trunk-brown` #7D6650，崎岖纹理，受光面 `trunk-highlight` 高光
- 底粗扎入土壤，顶细，扎实感
- 侧枝连接处有弧度（贝塞尔），禁止直线硬连

**动效**
1. 树叶飘落：随机 2–6 片缓慢下落+淡出，循环，固定种子
2. 整树轻摆 rotate(±1.5°)，4–6 秒周期 ease-in-out

### Codia 提示词

## 十一、复盘页面（情绪 × 效率 · 核心）

设计目标：用户带着"我最近还好吗"的心情打开，一眼获得情绪的整体感受，想深究时才展开细节。核心要回答两个问题：**我做哪类事会开心？哪类事让我累、需要加强奖励？**

采用远景 / 近景两层结构：**四颗情绪水晶球（远景，一眼感受）→ 点击展开情绪堆叠条（近景，读细节）**。

### 远景：四颗情绪水晶球

四颗等大的独立玻璃球，均匀一排：生产 · 日常 · 创造 · 娱乐。

```
   ○      ○      ○      ○
  生产    日常    创造    娱乐
  (赭)    (蓝)    (绿)    (绿)
  9h     7h     2h    1.5h
```

- **一球 = 一类效率活动**：四类各自独立成球，有间距、各自带标签。拆成独立球是为了：即便两类情绪相近（颜色相似），也不会在同一容器里糊成一团——**颜色编码情绪，位置 + 标签编码类别**
- **四球等大**：球大小固定，不随时间变。时间多少由水位表达即可，等大更整齐、不喧宾夺主
- **水位 = 真实用时**：满球 = 24h，水位 = 用时 / 24
- **水的颜色 = 该球主导情绪色**（MoodBlend 引擎，见「情绪水色引擎」）
  - 一眼读出：绿 = 愉悦，赭红 = 压力。不评判、不打分，只是"水的颜色"，符合「安全容纳」
- **透明的水 = 未追踪时间**：以清水形式呈现，意为"发生了，但不知道它的感受"
- **一句洞察**：球下方一句自动生成的温柔观察，是这页的灵魂，遵守「内容语气」

> 设计意图：引导用户多花时间给自己、多产生正向情绪——消遣类（创造/娱乐）水位偏低、刚需类（生产/日常）偏高时，对比本身就是温柔的提醒。（曾尝试"两球双腔 + 刚需/消遣分组"，但同腔内相近情绪色难分辨，改为四颗独立球；分组叙事放弃，保留纯净。）

**计量模型（重要）**：一个活动最多可打 **2 个效率标签**，记录时该段时间 **全额（100%）计入两个球**，不分权重。因此四类之和可能超过实际用时——每类各自对 24h 独立衡量，互不挤占。例：「做饭」可同属 日常 + 创造；「写代码」可同属 生产 + 创造。

**视觉处理**：走**极简玻璃感**（透明、折射、缓慢晃动的水面），与生命树的写实森林明确区分——避免两个签名元素互抢。boldness 上生命树仍是第一主角，水晶球克制。

**技术预期**：风格化的水（Canvas + TimelineView 画波动水面 + 缓慢晃动），非真实流体物理。目标是"感觉像水"。参考实现 [crystal-ball-v4.html](./crystal-ball-v4.html)。

### 近景：点击水球 → 情绪堆叠条

点任意一颗球，展开该类活动的情绪明细：

```
生产  9.5h
[愉悦][平静][还行][低落][压力][灰]
 .5h  1.5h  3h   1h   3h   .5h没标心情
这类事让你压力偏多，试试给相关目标调高奖励？
```

- 一条横向堆叠条 = 该类活动总时间
- 情绪分段：暖色情绪（愉悦 / 平静）排在**前面**，遵守「鼓励优先」
- **尾部浅灰段**（`time-untracked` #D2CEC4）= 记了活动但没标情绪的时间，暖灰非警告灰
- 可选出现一句温柔建议（压力偏多 → 提示调高奖励份额），衔接奖励系统
- **复盘报告全程不出现 emoji**：图例只用色点 + 名字 + 时长，建议语纯文字。emoji 只在记录打标签时出现

### 两种"没记录"的统一规则

| 情况 | 含义 | 呈现 |
|---|---|---|
| 有活动没标情绪 | 记了活动，没打心情标签 | 该活动堆叠条尾部浅灰段 |
| 完全未追踪 | 没记任何活动 | 水晶球里的透明水；堆叠条明细里单列一条浅灰「未追踪」 |

两者同用 `time-untracked` #D2CEC4，位置不同，语义清晰。

### 奖励模块（独立区块）

放在情绪可视化下方，与情绪×效率分开陈列，保持这页不拥挤：

- **未兑换奖励**：生命树里勾选完成的产出目标，按奖励层级色（🌱小确幸 / 🌟好好犒劳 / 🎯认真奖励 / 🏆里程碑）陈列，每条可「兑换」
- **奖池**：用户自定义的奖励条目，按层级归类。兑换时从对应层级奖池里挑一项
- 兑换动作有仪式感（庆祝级动效 0.6–0.8s），遵守「正反馈驱动」

## 十三、如何使用这份文档

**做任何 UI 决策时，先问三个问题：**

1. 用户在这个时刻的心理状态是什么？（参考第二节：核心使用场景）
2. 这个设计符合哪条原则？违反哪条原则？（参考第三节：五条设计原则）
3. 这个文字/提示的语气对吗？（参考第四节：内容语气）

**引入外部参考时（如 Mobbin）：**
不是"找好看的复制过来"，而是"找符合这套原则的执行方案"。
每一个借鉴都应能对应到某条设计原则。
